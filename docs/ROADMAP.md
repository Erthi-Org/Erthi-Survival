# Roadmap — Erthi Survival

## Phase 0 — foundations
- [x] Verify the Erthi repository and audit the upstream repositories at a preliminary level.
- [x] Document humanitarian scope, architectural boundaries and safety policy.
- [ ] Confirm the open-source license and written permission to reuse any Nexvary code.
- [ ] Complete source-code and CI audit of Emergency Mesh.

## Phase 1 — offline Android app
- [ ] Native Kotlin Android application with Arabic RTL and English translations.
- [ ] Offline evidence-based nuclear/radiological emergency guidance, with reviewed sources and dates.
- [ ] High-contrast emergency screen and accessible user flows.
- [ ] Automated build, tests, lint and emulator validation; produce installable test APK.

## Phase 2 — reviewed emergency content
- [ ] Review first-aid, decontamination, supplies and shelter advice with qualified specialists.
- [ ] Signed, versioned offline content updates and rollback.

## Phase 3 — optional resilient communications
- [ ] Review and selectively adapt eligible Emergency Mesh components with required permissions.
- [ ] Isolated local transport interfaces, explicit delivery-state UI, and no guaranteed rescue-contact claims.
- [ ] Battery, background execution, and multi-device transport testing.

## Phase 4 — release readiness
- [ ] Verify shelter data where legally and practically available.
- [ ] Accessibility, privacy, security, and reproducible release review.
- [ ] Publish limitations and responsible vulnerability reporting process.

Always distinguish documented, implemented, CI-tested, device-tested, and field-verified.
